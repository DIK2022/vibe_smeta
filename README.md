# PDF-планировка → 3D-модель → Excel-смета

Прототип системы, которая превращает планировку квартиры из PDF
в упрощённую 3D-модель, расставляет мебель, считает объёмы работ
и выгружает результат в Excel — со **сверкой источников данных**.

Проект собран как ответ на тестовое задание на вакансию
«Вайбкодер / AI-разработчик / Python — автоматизация строительных смет».

## Что делает

Конвейер обработки:

```
PDF-планировка → 2D-данные → 3D-модель → расстановка мебели
             → расчёт объёмов → сверка источников → Excel-смета
```

На выходе:

- **`apartment.obj`** — 3D-модель квартиры (открывается в Blender,
  3ds Max, Maya, SketchUp, онлайн-вьюерах).
- **`volumes.xlsx`** — Excel с тремя листами:
  - «Объёмы работ» — площади пола, стен, потолков, периметры,
    количество дверей и окон.
  - «Сверка источников» — сравнение площадей из экспликации
    и кружков на чертеже с цветовой подсветкой.
  - «Открытые вопросы» — позиции, по которым система не может
    принять решение автоматически.

Плюс интерактивное Streamlit-демо для наглядного просмотра
с тултипами при наведении.

## Быстрый старт

### Установка `uv`

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```

### Запуск

```bash
# 1. Установить Python 3.13 и зависимости
uv python install 3.13
uv sync

# 2. Сгенерировать обязательные артефакты (по ТЗ)
uv run build_model.py

# 3. Опционально: интерактивное демо
uv run streamlit run app.py
```

После шага 2 в корне появятся:

```
apartment.obj
volumes.xlsx
```

После шага 3 откроется браузер на `http://localhost:8501`.

```
vibe_smeta/
├── core.py               # Общая логика: данные, геометрия, сверка, экспорт
├── build_model.py        # CLI: создаёт apartment.obj и volumes.xlsx
├── app.py                # Streamlit-демо

├── .gitignore
└── README.md             # Этот файл
```

### Назначение файлов

**`core.py`** — вся логика в одном месте:

- `EXPLICATION` — площади из таблицы на чертеже.
- `DRAWING_MARKS` — площади с кружков на плане.
- `NAMING_CONFLICTS` — конфликты назначения помещений.
- `ROOMS` — геометрия комнат (полигоны + высота стен + тип пола).
- `FURNITURE` / `FURNITURE_RU` — размеры и русские названия мебели.
- `compare_sources()` — сверка экспликации и чертежа.
- `get_open_questions()` — список вопросов к заказчику.
- `build_all()` — сборка 3D-меша (вершины, грани, цвета).
- `build_all_with_meta()` — то же + метаданные для тултипов.
- `compute_volumes()` — расчёт объёмов.
- `export_obj_file()`, `export_excel_file()` — экспорт.

**`build_model.py`** — тонкая CLI-обёртка: вызывает `core.py`,
создаёт файлы, печатает отчёт в консоль.

**`app.py`** — Streamlit-интерфейс с вкладками: «3D-модель»,
«Сверка источников», «Открытые вопросы», «Объёмы», «Excel», «О решении».

### Геометрия помещений

| Помещение | Форма | Особенность |
|---|---|---|
| Кухня-Гостиная | Квадрат 5.93 × 5.93 с вырезом | Вырез под Прихожую и Санузел |
| Прихожая | Прямоугольник 1.63 × 2.10 | Внутри выреза Кухни-Гостиной |
| Санузел | Прямоугольник 1.05 × 2.10 | Внутри выреза Кухни-Гостиной |
| Балкон | Прямоугольник 4.00 × 1.60 | Ограждение 1.1 м (`wall_h`) |
| Спальня | L-форма 3.50 × 5.93 | Вырез под Ванную в правом нижнем углу |
| Ванная | Прямоугольник 2.20 × 2.90 | Внутри выреза Спальни |

### Ключевые решения

**1. Комнаты — соседние полигоны, не вложенные.**

Комнаты стыкуются вплотную, но не перекрываются. Это избегает
удвоения площадей, z-fighting полов и дублирования стен.

**2. Дедупликация стен.**

Общая стена между двумя комнатами рисуется один раз. Реализовано
через множество нормализованных рёбер: `(min_x, min_y, max_x, max_y)`.

**3. Разная толщина стен.**

Наружные — 250 мм, внутренние — 80 мм. Определяется автоматически
через `is_outer_edge` (сравнение с bounding box квартиры).

**4. Полигоны вместо прямоугольников.**

Комнаты описываются списком вершин, что позволяет задавать L-формы
с вырезами и точно считать площадь.

**5. Два источника площадей.**

Экспликация — официальный документ, по которому работает смета.
Кружки на чертеже — визуальные метки. Система хранит оба источника
и сравнивает их.

**6. Знаковая площадь для центроида.**

В `poly_centroid` используется **знаковая** площадь, а не `abs()`,
иначе для CW-полигонов центроид уходит за пределы фигуры
и фан-триангуляция даёт артефакты.

**7. Три листа Excel.**

Объёмы, сверка, открытые вопросы — разделены, чтобы сметчик видел
и результат, и проблемы данных, и точки, где нужно его решение.

## Обнаруженные проблемы в исходных данных

При разборе PDF выявлены **противоречия между экспликацией**
(таблица справа на чертеже) **и кружками** на плане.

### 1. Расхождения площадей

| Помещение | Экспликация | Чертёж | Разница |
|---|---|---|---|
| Прихожая | 9,87 м² | 3,40 м² | −65 % |
| Кухня-Гостиная | 35,45 м² | 52,07 м² | +47 % |
| Спальня | 12,42 м² | 20,72 м² | +67 % |
| Санузел | 2,09 м² | 2,09 м² | 0 % ✅ |
| Ванная | 6,73 м² | 6,80 м² | +1 % ✅ |
| Балкон | 9,50 м² | 9,74 м² | +2,5 % ✅ |
| Спальня №2 | 17,50 м² | — | нет кружка |
| **ИТОГО** | **93,56 м²** | **94,82 м²** | **+1,3 %** |

### 2. Нумерация кружков и таблицы не совпадает

На плане кружки ①–⑥, в таблице — строки 1–7. Это **разные системы
нумерации**. Например:

- **Кружок ②** = Кухня-Гостиная (52,07 м²),
- **Строка 2 в экспликации** = Санузел (2,09 м²).

Совпадающие по смыслу позиции имеют разные номера:

| Помещение | № в таблице | № кружка |
|---|---|---|
| Санузел | 2 | ④ |
| Ванная | 3 | ⑤ |
| Кухня-Гостиная | 4 | ② |
| Спальня | 5 | ③ |
| Балкон | 7 | ⑥ |

**Вывод:** сопоставление возможно только по названию или площади,
не по номеру. Система матчит позиции по ключу (названию), поэтому
работает корректно.

### 3. Расхождения по отдельным помещениям

**Кухня-Гостиная: 35,45 vs 52,07.** Разница ~17 м². Кружок ②
показывает **весь большой блок целиком**, а таблица — **только
кухню-гостиную без вырезов**. Сумма по трём строкам таблицы
(Санузел 2,09 + Прихожая 9,87 + Кухня-Гостиная 35,45 = 47,41 м²)
близка к площади блока 46,58 м² после вычета кружков ① и ④.
Это объясняет расхождение: **экспликация разбивает блок на три
части, кружок ② показывает весь блок**.

**Спальня и Спальня №2.** В геометрии оставлена только Спальня —
она присутствует на чертеже как L-форма. Спальня №2 в геометрии
отсутствует: на плане нет отдельного помещения с площадью 17,50 м².
Это вынесено в «Открытые вопросы».

### 4. Возможные причины расхождений

- **Разные определения площади.** БТИ считает «общую площадь»
  без балконов и с понижающим коэффициентом для лоджий (0,5).
  Дизайнер — по внутренним стенам.
- **Разные версии проекта.** Чертёж может быть до перепланировки,
  а экспликация — после (или наоборот).
- **ГКЛ-конструкции.** Гипсокартонные короба, ниши, встроенные
  шкафы по-разному учитываются в площади.
- **Разные источники.** Кружки часто ставятся для визуальной
  ориентировки, экспликация — официальный документ БТИ.

### 5. Открытые вопросы к заказчику

1. Какую цифру использовать по расходящимся позициям — из экспликации
   или с чертежа?
2. Есть ли между документами перепланировка?
3. Что считать источником истины при расхождении номеров?
4. Что такое «Спальня №2» (17,50 м²) — есть ли она на плане?
5. Как применяется понижающий коэффициент для балкона в смете?

Все эти вопросы автоматически попадают на лист **«Открытые вопросы»**
в Excel и на вкладку в Streamlit.

## Как система работает с противоречиями

Вместо того чтобы молча выбрать одну цифру, реализована
**сверка источников**:

**Лист «Сверка источников»** в Excel — с цветовой индикацией:

- 🟩 **зелёный** — OK (расхождение ≤ 5 %).
- 🟥 **красный** — существенное расхождение.
- 🟨 **жёлтый** — конфликт назначения помещения.
- 🟧 **оранжевый** — нет метки на чертеже (не с чем сравнить).
- ⬜ **серый** — итоговая строка.

**Лист «Открытые вопросы»** — список позиций, по которым нужно
решение заказчика.

**В Streamlit** — отдельные вкладки «Сверка источников»
и «Открытые вопросы». В сайдбаре — переключатель источника:
экспликация / чертёж / геометрия.

По умолчанию используется **экспликация** — официальный документ,
по которому работает смета. Чертёж — для визуализации геометрии.

## Что автоматизировано, что вручную

### Автоматизировано

- Построение 3D-модели: пол, стены, потолок (опционально), мебель.
- **Разная толщина стен:** наружные 250 мм, внутренние 80 мм.
- **Высота стен по помещению:** балкон — ограждение 1.1 м,
  остальные — 2.9 м.
- Расстановка мебели по правилам с учётом проходов:
  - кухня вдоль северной стены,
  - диван в левой зоне,
  - стол со стульями правее — **не перекрывает проход**,
  - кровать и шкаф — вдоль дальней стены,
  - прихожая — **без мебели**, только проход.
- Дедупликация стен: общая стена между комнатами рисуется один раз.
- Расчёт объёмов: площадь пола, стен (за вычетом проёмов), потолка,
  периметр, количество дверей и окон.
- **Сверка источников**: сравнение экспликации и чертежа с подсветкой.
- **Автоматическое формирование списка открытых вопросов.**
- **Тултипы в Streamlit:** «Кухня-Гостиная — Наружная стена»,
  «Спальня — Кровать (1.6×2.0 м)».
- Выгрузка в Excel с тремя листами.
- Экспорт 3D-модели в `.obj`.

### Вручную

- **Первичная оцифровка координат помещений с PDF.** Прочитал
  размерные линии с чертежа, задал полигоны в `ROOMS`. Точность ±10–15 %.
- Проверка логичности расстановки мебели.
- Выбор источника площадей для сметы (по умолчанию — экспликация).

## Ограничения прототипа

Прототип **не является точной копией** планировки:

- **Геометрия приблизительная.** Координаты оцифрованы вручную
  с точностью ±10–15 %. Пропорции комнат близки к оригиналу,
  но не совпадают 1:1.
- **Проёмы (двери, окна) не вырезаны в 3D** — только учтены
  в расчёте площади стен.
- **Мебель типовая**, расставлена по правилам, а не по дизайн-проекту.
- **Помещения описываются как соседние полигоны**, а не как пустота
  между стенами. Полноценная BIM-модель (Revit / IFC) — следующий этап.
- **Спальня №2 отсутствует в геометрии** — на плане нет отдельного
  помещения с такой площадью. Вынесено в открытые вопросы.

Для **точной** геометрии требуется один из подходов:

| Подход | Точность | Трудоёмкость |
|---|---|---|
| CV-парсинг векторного PDF (OpenCV + HoughLines) | Высокая | 4–8 часов |
| LLM Vision API (Claude / GPT-4o) → JSON с полигонами | Средняя | 1–2 часа |
| Ручная оцифровка в QGIS / AutoCAD → GeoJSON | Высокая | 2–4 часа |
| Revit / ArchiCAD → экспорт IFC | Очень высокая | 8+ часов |

Это отражено в разделе «Развитие».

### 3D-модель `apartment.obj`

Формат OBJ — универсальный, открывается в:

- **Blender** — File → Import → Wavefront (.obj)
- **3ds Max** — File → Import
- **Maya** — File → Import
- **SketchUp** — File → Import
- **Онлайн-вьюеры:** https://3dviewer.net, https://sandbox.babylonjs.com

Формат не требует `numpy` при импорте, поэтому работает
даже в сборках Blender из репозиториев Linux (Debian / Ubuntu / Astra),
где встроенный Python идёт без `numpy`.

## Развитие

### Ближайшие шаги

1. **LLM Vision API (Claude / GPT-4o)** — авто-извлечение координат
   стен и помещений из PDF. Промпт: «Верни JSON с полигонами
   помещений, высотами, количеством проёмов».
2. **CV-парсинг векторного PDF** — OpenCV + HoughLines для детекции
